# 第一部分 · 项目说明

## 1.1 一句话

基于原作音乐 `asset/music/music.mp3`（120 BPM，156 s，78 小节）制作的高规格像素 MV（Hi-bit / Neo-Retro Pixel Action FX）：**保留原版战斗 UI 与点阵质感**，叠加现代演出——3D 运镜、色差、残影、黑白反相冲击帧、辉光、故障撕裂、VHS 倒带，以及一段**第一人称体素 3D**。所有画面严格对齐音乐的 16 分音符网格。

## 1.2 叙事

- 屠杀线（Genocide）。主角是冷酷清空地底世界的玩家（名字 **BOMEI**，**LV 19**，HP 上限 **92**）。
- 整场战斗里玩家的攻击**一次也打不中**（全是 MISS）；「仁慈」被删除，「物品」「行动」被击碎，最后只剩「战斗」。
- 玩家只被真正“打死”一次（第 36 小节）：心碎 → 读档 → VHS 倒带 → 同一段攻击重放、冷静躲过。
- 最后 Sans 耗尽力气睡着，红心顶着战斗框一路推到「战斗」按钮上，**直接斩断按钮本身**——用打破第四面墙的方式赢下战斗。
- 结尾没有胜利的欢呼，只剩一个问题「* 这就是你想要的吗？」，和音乐结束后的几秒寂静。

## 1.3 成片规格

- 16:9 完整版：1920×1080、60 fps、**160 s**（音乐 156 s + 4 s 静默尾声），只用游戏原声 + 原版音效。
- （可选，最后再做）TikTok 竖屏版 `?cut=tiktok`：1080×1920、约 71 s，从第 44 小节「战斗」被选中开始到结尾（静默尾声留 3.5 s），见第四部分末尾。

## 1.6 本片专属技术要点

- **骨头参数化生成**（任意长度、粗细、角度、白/蓝），不要用贴图拉伸；蓝骨沿边缘冒细小冷焰火星。
- **兽颅炮** `H.cannon({tSpawn, fires:[t...], beamDur, scale, pos(t)->{x,y,ang}})`：故障撕裂中“咬合”出现 → 蓄力（张嘴帧）→ 开火（光束宽度先爆后收、发光层）→ 收回。炮的朝向、位置可以是时间函数。
- **击碎 UI** `H.shatter(t, rect, drawFn, {chunk, force})`：把一块 UI（按钮、HP 条）当作图像切块飞散；**溶解** `H.dissolve`：像素逐个消失（仁慈被删除）。
- `post.js`：像素世界是一张平面，由**真正的 3D 相机**拍摄（俯仰/偏航/翻滚/推拉），远处有一层视差虚空网格；双层辉光、径向色差、黑白反相冲击帧、故障切片、甩镜运动模糊、VHS、点阵网格、暗角。
- **第一人称体素**（`src/voxel.js`）：低分辨率帧缓冲（保持像素颗粒感）里画定向长方体（骨头 = 骨干 + 关节块、墙、地砖、光束），光照 + 雾；Sans 和兽颅是**公告板**（billboard），兽颅按“光束在镜头里的方向”转正；自发光写进 alpha 通道供辉光使用。
- **碰撞校验** `check.cjs`：240 Hz 采样整首，白骨和光炮**从未碰到心**、蓝骨只在心静止时穿过；第一人称段同样检查光炮/白骨与镜头的距离（`MV.checkPov()`）。HP 只在画面上真的被打中时才变化：砸到 HP 条（UI 受损，不是心受伤）、第 36 小节的死亡、第 62 小节正面的光炮、第 63 小节墙里的骨头。
- 音效：原版音效按时间表触发（骨刺 BoneStab、炮蓄力 GasterBlaster / 开火 GasterBlast、砸墙 Slam、斩击 PlayerFight、心碎 HeartSplit/HeartShatter、菜单 MenuCursor/MenuSelect、打字 BattleText/SansSpeak、蓝心「叮」Ding、预警 Warning、受伤 PlayerDamaged）。
- 心的走位由**规划器**挑选：每一步垂直于来袭方向、留在下一拍更小的墙内、离所有在飞的弹幕至少 22 px。把它写成工具函数，不要每一步手调坐标。

# 第二部分 · 通用框架要求（六个 MV 共用，必须照做）

> 这六部 MV 原本是同一套自研「无状态时间轴 + 像素画布 + WebGL 后期 + 无头浏览器逐帧导出」框架，一部一部迭代出来的。复刻时**先把这套框架搭起来并验证**，再碰任何分镜。

## 2.1 技术栈与目录

- **纯静态网页**：一个 `index.html` 按顺序 `<script src="src/xxx.js">` 加载所有模块；**不用打包器、不用前端框架、运行时零 npm 依赖**。全局命名空间 `window.MV`，每个文件是一个 IIFE，往 `MV` 上挂东西。
- 画布 `<canvas id="mv" width="1920" height="1080">`；**世界坐标 960×540**（原作 640×480 的战斗布局 1:1 居中，左右多出来的地方留给运镜和特效），像素世界按 2 倍放大到 1080p。角色精灵 2 倍像素、心和弹幕 1 倍像素——**和原作一样的混合分辨率**，不要把所有东西统一缩放。
- 2D 用 Canvas2D（`imageSmoothingEnabled = false`，坐标一律 `Math.round`），后期和 3D 用 WebGL（自己写一个 `m3.js` 小矩阵库，不引入 three.js）。
- Node.js（≥18）+ Playwright（Chromium）+ ffmpeg 只用在 `tools/` 的离线脚本里；Python（numpy / scipy / librosa / pillow）只用在分析与素材打包脚本里。

推荐目录（与原工程一致）：

## 2.2 核心原则：一切都是时间 t 的纯函数

- 任何一帧都必须能**单独**渲染出来：实时播放、拖动进度条、逐帧导出、倒带（VHS 回放）、慢动作，全部走同一套代码。
- **禁止** `Math.random()`、禁止跨帧累积状态（“上一帧的位置 + 速度”）。随机一律用基于哈希 / 种子的确定性函数：`U.hash(x)`、`U.hash2(x,y)`、`U.noise(x)`、`U.rng(seed)`（mulberry 类）。
- 物理（重力心、蓝心砸墙、风推心）要么写成解析式，要么**预先离线模拟后烘焙成采样**（`Track.bake(t0, dt, {x:[...], y:[...]})`），播放时只插值。
- 引擎 API（建议照抄这套语义）：
  - `new MV.Track(init)`：多通道关键帧轨道。`.to(t0, t1, vals, ease)`、`.set(t, vals)`、`.hop(t0, t1, vals, h)`（抛物线跳）、`.bake(...)`、`.at(t)` 返回该时刻全部通道值。段与段从“上一段到达的值”混到目标值。
  - `new MV.Steps(v)`：分段常量（姿态、模式、开关），`.set(t, v)`、`.at(t)`、`.since(t)`（当前值已持续多久）。
  - `TL.add({t0, t1, z, draw(ctx, emi, t, S), hit?(t, x, y)})`：一个“活在 [t0,t1) 的可绘制事件”。按 z 排序绘制。`TL.active(t)` 用二分找出当前活着的事件。会伤人的弹幕必须实现 `hit(t, x, y)`（该时刻点 (x,y) 是否在弹幕里），页面暴露 `MV.checkHits(t0, t1)` 给 check.cjs 用。
  - `TL.impact(t, {amp, dx, dy, zoom, rot, inv, bw, flash, ca, dur})`：冲击——震屏（方向踢 + 随机抖）、推镜、旋转、反相帧、黑白帧、闪白、色差，全部随时间指数衰减，由 `TL.fxAt(t)` 汇总。
  - `TL.glitch(t0, t1, amt)`、`TL.shock(t, {...})`（屏幕冲击波）、`TL.burst(t0, {...})`（解析式粒子爆发，无模拟状态）、`TL.ring(...)`（像素圆环）。
  - 时间重映射：`TL.remap(t0, t1, f)`（画面显示 f(t) 而不是 t，用于 VHS 倒带）、`TL.hitStop(t, hold, catchUp)`（顿帧后用 Hermite 曲线追回音乐，无跳变）、`TL.slowmo(t, W, a)`（先慢后快、首尾速率为 1 的慢动作）。**音乐永远不停，只有画面时间被重映射**。
  - 音效表：`TL.sfx.push({t, name, vol, rate, end, fade})`，播放器用 WebAudio 提前 0.25 s 排程，导出时由 render.cjs 混进音轨——两边读同一张表。
- 每个 `draw(ctx, emi, t)` 都拿到两张画布：`ctx` 是颜色层，`emi` 是**自发光层**（辉光的来源）。会发光的东西（光炮、魔法、眼睛、火）要同时往 `emi` 画。

## 2.3 音乐网格（卡点的唯一依据）

- `tools/analyze_music.py`（librosa）分析音乐，写出 `src/analysis.js`：`window.MV_ANALYSIS = { bpm, offset(第 0 小节第 0 拍的秒数), sixteenth, barLength, duration, bars, slots:{kick, snare, tone, full}(每个 16 分音符格子的实测起音强度 0–1), env:{rms,...}(包络), envFps, sections:[{bar0, bar1, name}] }`。
- 先用 `beat_track` 粗估 BPM，再**用 16 个相位逐一和主节奏型做相关**挑出真正的第一拍；检查全曲是否恒速（游戏原曲通常是恒速的，同人混音/未完成版要分段核对）。
- `util.js` 里提供 `T.at(bar, beat=0, s16=0)`（小节/拍/16 分 → 视频秒，允许小数、溢出、负数）、`T.slot(t)`、`T.barOf(t)`、`T.acc(slot, band)`、`T.env(t, band)`、`T.pulse(t, period)`、`T.accPulse(t, band)`、`T.section(t)`。
- **所有事件都写成 `T.at(...)`**，不允许出现手写的“37.42 秒”。
- 卡点约定：弹幕在音符**上**到达最长 / 命中；炮在拍上开火；心的闪避在**前一个八分音符**完成；镜头硬切落在重拍；震动强度、粒子数量可以读该 16 分格的实测强度 `T.acc`。
- 冷开场、多首曲子拼接时，`T.pre` / `T.off` 等偏移写在 util.js 一处，`MV.MUSIC = [{src, t0, dur, off}]` 列出每个音频文件在视频时间轴上的起点（`src` 是相对 `index.html` 的路径，本仓库里是 `asset/music/…`）；播放器和导出都读它。

## 2.4 素材管线

- `tools/import_assets.py`：把 `asset/` 里的精灵表切片（按 spriters-resource 表格的格子或手工坐标）、透明化、去背景，原作音效 wav/ogg 用 ffmpeg 转 mp3，统统打成 `src/assets.js`：`window.MV_ASSETS = { img:{name: dataURI}, sfx:{name: dataURI}, meta:{锚点/帧表} }`。**这样双击 index.html（file://）也能跑，没有 CORS 问题。**
- 战斗 UI（心、四个按钮、HP/KR、攻击靶、斩击、对话气泡、字体、菜单音效）统一用 `asset/ui-kit-c2-sans-fight/`（原作素材，带锚点 meta.json）。
- 中文：`tools/make_font.py` 扫描 `src/*.js` 里用到的所有非 ASCII 字符，用 16 px 宋体（`C:/Windows/Fonts/simsun.ttc`，或 GNU Unifont）渲染成 1-bit 点阵，写进 `src/glyphs.js`；画面上所有中文都是点阵字，和原作中文版的观感一致。英文/数字用原作位图字体。
- 角色动作：优先用原作精灵帧；需要原作没有的动作时，**把精灵切成部件做骨骼 rig**（关节点手工标定，或在录像里逐帧拟合），而不是重画一个风格不同的角色。
- 生成文件（analysis.js / assets.js / glyphs.js）**永远不手改**，改脚本重新生成。

## 2.5 渲染层次与后期（post.js）

- 每帧：`scene.render(t)` → 求值所有 Track / Steps → 在离屏的**世界画布**（960×540 + 四周留边，供运镜不露边）上画背景 → 弹幕 → 角色 → 战斗框/HUD；同时画**发光层**；再画不受相机影响的**屏幕层**（字幕、遮幅、读档界面等）。
- `post.js`（WebGL）：把世界画布当作 3D 空间中的一张平面，用**真的 3D 透视相机**去拍（pitch / yaw / roll / dolly / 平移），远处可有一层视差虚空网格；然后依次叠加：双层辉光（emi 层）、径向色差、黑白反相冲击帧、黑白阈值帧、故障切片 / RGB 撕裂、甩镜运动模糊、VHS（倒带时）、点阵网格 / 扫描线、暗角、胶片颗粒。
- 镜头语言要“现代”但画面要“原作”：**像素永远是方的、不糊**（后期在 1080p 上做，世界层最近邻放大）。

## 2.6 播放器（main.js / index.html）

- 空格 / Z / 回车：播放暂停；← →：±2 s（按住 Shift：±1 小节）；D：调试信息（`t / 小节 / 拍 / 16 分 / 段落名`）；H：干净画面（隐藏 UI，截图用）；点击底部进度条跳转。
- URL 参数：`?t=64`（从 64 秒开始）、`?lat=0.03`（音画延迟校准）、`?lab=<name>`（样片）、`?render=1&w=1920&h=1080`（导出模式：只暴露 `MV.exportFrame(t)` 和 `MV.ready`）、`?clean`。
- 音乐用 `<audio>` 元素按 `MV.MUSIC` 的偏移播放并以它为时钟；音效用 WebAudio 解码后按 `TL.sfx` 排程。第一次按播放要等音效全部解码完再开始。

## 2.7 工具（tools/）

> 本项目的 `tools/` 已经附上原工程的全部脚本（路径改成了本仓库布局），**先读 `tools/README.md`**。下表是通用的那几样；各项目专属的检查工具（例如 mft 的 `beatcheck.cjs`、mtt-neo 的 `cutaudit.cjs` / `camcheck.cjs`）也在里面。可以直接用，也可以照着重写，但页面要先提供它们用到的接口（`MV.ready`、`MV.exportFrame`、`MV.checkHits` 等）。

| 脚本 | 作用 |
| --- | --- |
| `serve.cjs` | 无缓存静态服务器（预览 `http://localhost:4173`） |
| `pw.cjs` | 解析 Playwright；页面一律用 `file:///…/index.html?…` 打开并加 `--allow-file-access-from-files`；`--gpu` 时 `--use-angle=d3d11 --ignore-gpu-blocklist --enable-gpu-rasterization`，否则 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` |
| `frames.cjs <outDir> <t...> [--gpu --w --h --lab]` | 渲染指定时刻的静帧（**最常用的检查手段**） |
| `render.cjs [--t0 --t1 --fps=60 --w --h --workers --gpu --vcodec=h264_nvenc --frames=dir --out]` | 多个无头 Chromium 并行调用 `MV.exportFrame(t)` 拿 JPEG → 管道喂给 ffmpeg；同时把 `MV.MUSIC` 的各段音乐按偏移解码（`-af aresample=resampler=soxr`）+ `TL.sfx` 全部音效混成 48 kHz WAV，带 5 ms 前视峰值限制器（只压冲出去的瞬态），AAC 320k，`-movflags +faststart` |
| `check.cjs [bar0 bar1]` | 以 240 Hz 采样整段：白色弹幕/光束**从不碰到心**（剧本写明的命中除外）、蓝色弹幕只在心静止时穿过、弹幕密度/节奏统计；有问题就打印小节·16 分位置 |
| `sheet.py` / `contact_sheet.py` | 把一串静帧拼成联系表（contact sheet），一眼看完一段 |
| `analyze_music.py` / `explore_*.py` / `plot_music.py` | 音乐分析与可视化（频段能量、节奏型相关、自相似矩阵分段） |
| `import_assets.py` / `slice_sheet.py` / `make_font.py` | 素材打包、精灵表切片、点阵字 |
| `eval.cjs` | 在页面里执行一段 JS 打印结果（查某时刻某轨道的值） |

导出规格：**1920×1080、60 fps、H.264（NVENC：`-preset p5 -rc vbr -cq 19 -b:v 0`；或 libx264 `-crf 20 -tune animation`）、yuv420p、AAC 320k**。不加 `--gpu` 用 SwiftShader 也能跑，只是很慢。

## 2.8 画面与叙事的共同约束

- **原作 UI 本地化风格**：战斗框、HUD（名字 / LV / HP 条 / KR）、四个按钮、打字机文本（`* ` 开头、逐字出现带打字音）全部按原作像素位置与比例；中文文案参考原作官方中文。
- 弹幕命中与否必须“说得通”：心被打中 → 红闪 + 受伤音 + HP 真的掉；没写命中的地方，弹幕**绝不**碰到心（check.cjs 验证）。
- 原作没有的演出（3D 运镜、第一人称、2D→3D 切换、打破第四面墙）都要能从原作战斗机制里**长出来**：先用原作的语言立住规则，再打破它。
- 所有对白、旁白、字幕先写进剧本表（小节·16 分 → 文本 → 说话人 → 打字速度），再进代码。

# 第三部分 · 工作方式（最重要：逐步推进，切勿一次成片）

> ⚠️ **再说一遍：不要试图一次性写完整部 MV 再导出看效果。** 原作每一部都是几十轮“做一小段 → 出静帧 → 出小样 → 对照原作和剧本挑毛病 → 改”迭代出来的。一次成片的结果一定是：节奏全错位、弹幕穿心、镜头乱跳、角色走样，而且错误叠在一起无从下手。

## 3.1 必须遵守的推进节奏

1. **阶段 0 · 读与看（不写代码）**
   - 把本 PROMPT 从头读到尾，列出 `asset/` 里每个文件是什么、会用在哪一段。
   - 用 ffmpeg 从 `asset/record/` 的原作录像里抽帧（例如每 0.5 s 一张，再拼联系表），对照本文的分镜逐段看懂原作的 UI 位置、弹幕形态、角色动作、文字内容。把观察写进 `work/notes.md`。
   - 输出：素材清单 + 你理解的分段表（小节范围 → 内容），**先给用户确认**。
2. **阶段 1 · 框架骨架**
   - 搭 `index.html` / util / engine / main / scene / post / serve / frames / render / check。
   - 跑音乐分析，**验证网格**：做一个“节拍器样片”（每拍闪一次、每小节第一拍大闪、屏幕角落显示小节号），导出 20–30 秒带声音的小样，**亲自核对**画面闪光和听到的鼓点是否对齐（误差 < 1 帧）。网格不对，后面全部白做。
   - 输出：节拍器小样 + `analysis.js` 的关键数字（BPM、offset、总小节数、段落表）。
3. **阶段 2 · 素材入库**
   - 切精灵、打包 assets.js、生成字形；做一张“素材总览”静帧（所有精灵、所有动画帧、所有字体一字排开），检查透明边、锚点、尺寸是否正确。
   - 搭原作战斗场景的**静态还原**：一帧和原作录像截图并排对比，UI 像素位置对上为止。
4. **阶段 3 · 逐段编舞（核心循环，每次只做 2–8 小节）**
   - 写这一段的 `tl_xxx.js`。
   - `frames.cjs` 渲染这一段的关键时刻静帧（每个重拍、每个命中、每次镜头切换前后各一张），拼成联系表自己先看。
   - `check.cjs <bar0> <bar1>` 跑碰撞与密度检查，必须 0 违规。
   - `render.cjs --t0 --t1` 导出**这一段 + 前后各 1 小节**的带声小样，完整看一遍、听一遍：卡点是否在音符上、镜头是否有莫名的跳变、文字是否读得完。
   - 把小样和联系表交给用户确认，**得到确认再做下一段**。
   - 每段做完 `git commit`，提交说明写“小节范围 + 做了什么”。
5. **阶段 4 · 段与段的衔接**：每做完相邻两段，专门检查交界处前后 2 小节（镜头连续性、状态是否突变、HP / UI 状态是否一致）。
6. **阶段 5 · 全片**：所有段都单独通过后，才导出整片；整片再从头看一遍，列问题单逐条回到阶段 3 修。

## 3.2 自检清单（每段都要过）

- [ ] 所有时间都是 `T.at(...)` 写的，没有手写秒数。
- [ ] 任意拖动到这一段中间的任意时刻，画面都正确（无状态）；倒着拖也正确。
- [ ] `check.cjs` 0 违规；剧本里写明的“命中”才会命中，HP 变化与画面一致。
- [ ] 重拍上有东西发生（命中 / 切镜 / 冲击），弱拍上不乱闪。
- [ ] 文字出现时间够读完（中文按每字 ≥ 1 个 16 分音符估算），打字音跟着字出。
- [ ] 像素没有被插值糊掉；没有露出世界画布的边。
- [ ] 与原作录像对照：UI 位置、精灵造型、颜色、音效用对了。
- [ ] 帧率：实时播放 1080p 能跑满 60 fps（不行就降低世界层分辨率或减少粒子，**不能**靠丢帧）。

## 3.3 禁止事项

- ❌ 一次性生成所有 `tl_*.js` 然后整片导出。
- ❌ 没看过静帧/小样就宣布“这一段完成了”。
- ❌ 猜原作的 UI 位置、文案、弹幕形态——不确定就去录像里抽帧确认。
- ❌ 为了赶进度删掉剧本里写明的镜头或卡点；确实做不到要先和用户说明并给替代方案。
- ❌ 写大段设计长文或巨型注释代替实现（原工程的约定：剧本只看剧本文件，代码注释只写“为什么”）。
- ❌ 引入 three.js / React / 打包器 / 运行时 CDN 依赖。

# 第四部分 · 超详细分镜稿

> 记法：`B.k.s` = 第 B 小节第 k 拍（0–3）第 s 个 16 分（0–3）；代码里写 `T.at(B, k, s)`。时间 = 0.04 + 2·B + 0.5·k + 0.125·s 秒。
> 每段末尾的「验收」是这一段交给用户之前必须自己先确认的点。**一段一段做，一段一段交。**
> 推荐文件划分：`tl_intro.js`(0–7) · `tl_dropA.js`(8–15) · `tl_blue.js`(16–23) · `tl_cannon.js`(24–31) · `tl_climax.js`(32–39) · `tl_counter.js`(40–47) · `tl_frenzy.js`(48–55) · `tl_final.js`(56–63) · `tl_end.js`(64–77 + 尾声) · `tl_tiktok.js`(竖屏版)。

## 段 1 · 第 0–3 小节（0.04–8.04 s）· 干声 riff 前奏：画框、开场白、第一次 MISS

音乐：只有干声主 riff。

| 时刻 | 画面 / 镜头 | 音效 |
| --- | --- | --- |
| 0.0.0 起 | 全黑。**战斗框随每个 riff 音符画出一段**（四条边按笔画顺序生长，笔头是一个发光的点），**镜头在 3D 里跟拍笔头**（轻微俯仰 + 平移，跟着笔头绕框一圈） | 每个 riff 音符可配极轻的菜单咔嗒 |
| 0–1 小节 | HUD（BOMEI / LV 19 / HP 条 / 92/92）与四个按钮**逐音符弹出**（每个元素从 0 缩放弹到 1，带一次 outBack） | MenuCursor |
| 1–2 小节 | 宽框里的开场白「* 你感觉你将要经历一段糟糕的时光。」——**每个 riff 音符打出一个词**（不是逐字匀速，而是按 riff 的重音分词跳出） | BattleText |
| 2–3 小节 | 光标选中「战斗」→ 攻击靶出现，光标从左向右滑；**在下拍正中命中**靶心 → 斩击 6 帧 → **Sans 侧身闪避**（整个人水平滑开再回来）→ 头顶 **MISS** | MenuSelect、PlayerFight |

验收：笔头和 riff 音符一一对应；开场白每个词都在 riff 音符上；MISS 的位置是 Sans 原本站的地方。

## 段 2 · 第 4–7 小节（8.04–16.04 s）· riff + 贝斯：骨头钢琴卷帘

| 时刻 | 画面 / 镜头 |
| --- | --- |
| 4–6 小节 | 心进入窄框。**骨头按 riff 的音高像钢琴卷帘一样从框底升起**（音高越高骨头越长，横向位置按时间排开、从右向左卷过），心在骨头之间的低处移动 |
| 5–7 小节 | **滑骨逐拍掠过**（每拍一根，从一侧横扫到另一侧，高低交替），心提前八分音符跳/让 |
| 7 小节 | 低频推升：画面逐渐压暗，最后一拍**镜头推到 Sans 脸上**，眼窝熄灭（换 NoEyes 头），**16 分音符故障抖动**（每个 16 分一次小幅故障切片） |

验收：骨头长度跟 riff 音高对得上（低音短、高音长）；第 7 小节最后一拍镜头已贴脸、8.0.0 正好切走。

## 段 3 · 第 8–15 小节（16.04–32.04 s）· DROP A：白骨弹幕

| 时刻 | 画面 / 镜头 |
| --- | --- |
| 8.0.0 | **反相冲击帧**（inv 约 1 个 16 分）+ 四壁骨刺同时爆发；镜头从 Sans 脸部猛拉回全景 |
| 8–9 | **每拍一道骨墙**从侧面推来，墙上的**缺口每拍换位置**，心**提前八分音符翻滚**（带残影）钻进缺口 |
| 10–11 | **窄框骨雨**：骨头从上方落下，数量/长短**按鼓点强度 `T.acc` 生成**；每拍在心**刚离开的那半边**从地面或天花板刺出一簇骨头——数量、长短、位置、齐刺或错开**每次都不同** |
| 12–13 | **宽框透视倾斜**：战斗框变宽，相机绕 x 轴俯仰让框面倾斜成透视；心绕圈跑，**骨刺追着心的轨迹**从地面依次刺出 |
| 14–15 | **巨骨刺穿「物品」按钮**（按钮被刺穿、碎裂飞散 `H.shatter`）；**一根骨头砸中 HP 条**（HP 条变形掉色、迸出紫/黄色粒子——这是 UI 受损，不是心受伤） |

验收：check.cjs 0 违规；每个缺口都在拍上对准心的落点；骨雨密度随鼓点起伏可见。

## 段 4 · 第 16–19 小节（32.04–40.04 s）· 蓝骨规则

规则：**白骨必须移动才能躲，蓝骨必须静止才能穿过**。

| 时刻 | 画面 / 镜头 |
| --- | --- |
| 16 | 第一根蓝柱来之前，心**急刹定格**（带一个小小的停顿顿帧）；**蓝光柱穿身而过**的瞬间：去饱和 + 冷色调 + 心跳脉冲（暗角随心跳一收一放） |
| 16–17 | 蓝骨与白骨交替：白来就动，蓝来就停；蓝骨边缘冒冷焰火星 |
| 18 | **一根巨型蓝柱缓慢碾过**整个框（占满框高、慢速横移），心全程纹丝不动，画面在它经过时最冷最暗 |
| 19 | 收尾一组白骨把心逼回框中央，为蓝心做准备 |

验收：心在蓝骨穿过的整段时间里速度严格为 0（check.cjs 会检）。

## 段 5 · 第 20–23 小节（40.04–48.04 s）· 蓝心重力：砸墙、跑酷

物理按 c2-sans-fight 模拟器（见 1.5），**离线模拟后烘焙**进 Track。

| 时刻 | 画面 / 镜头 |
| --- | --- |
| 20.0.0 | Sans 甩手（**原版四方向挥手动画**：HandDown/Up/Left/Right 4–5 帧），心变蓝（「叮」Ding），以 750–900 px/s 砸向墙；**墙体凹陷开裂**（框线在撞击点向外弯、裂纹像素线），砸墙音 Slam + 冲击 impact |
| 20–21 | 连续甩向四壁；**心尖始终朝着“下”的方向**（重力方向变了，心的朝向跟着转）；红色预警线 → 0.33 s 后骨刺从被砸的那面墙刺出 |
| 22 | **砸穿地板**：框底破洞，心掉出战斗框**落到 HP 条上**，然后**踩着四个按钮跑酷**（战斗→行动→物品→仁慈 依次跳过，每跳一下脚下的按钮弹一下，**身后刚离开的位置冒出骨头**） |
| 23 | 被拽回框内**贴在天花板上**，像弹球一样被甩来甩去；最后一拍回到红心 |

验收：心的朝向与重力方向一致；砸墙瞬间有凹陷；跑酷每一跳都踩在拍上。

## 段 6 · 第 24–31 小节（48.04–64.04 s）· 兽颅炮台

| 时刻 | 画面 / 镜头 |
| --- | --- |
| 24 | 兽颅炮在**故障撕裂中咬合出现**（下颚开合一次），蓄力 → **每一炮都开在拍上**，心永远领先光束一步 |
| 25 | **十字 / X 形交叉**：两两成对，十字与 X 交替 |

## 段 9 · 第 48–55 小节（96.04–112.04 s）· 捷径、平台连关、HUD 字母开火

**48–49 · 走捷径**：Sans **每拍瞬移**到场地另一处（白色光缝 + 残影），身旁两门炮锁定心开火，或射出**一扇骨镖**（扇形，缺口正好留在心静止的位置）；心只在必要时侧身让出射线。回到中间后他**挥手两次**，心随之变蓝、先被砸向地面、再被甩上天花板，落到第 50 小节的传送带上。

**50–53 · 平台连关**（每小节一关，对应模拟器四种平台攻击，**镜头横版跟拍**）：
- **50（platforms3）**：上下两条**反向传送带**，心逆着传送带奔跑、在两层之间跳跃，骨头从地面和天花板贴着它刚离开的位置滑过；最后**连跳两下**躲开左右夹来的骨头。
- **51（platformblaster）**：两端炮台**轮流沿车道开火**，心每拍换一层。
- **52（platforms2）**：传送带塌落，**一级级短台阶从骨床里升起、心踩过就碎**，骨床随之上涨，炮台扫射它刚离开的台阶高度。
- **53（platforms4）**：心站在一块**右移的平台**上，穿过一排排**上下滑动的骨头柱**，每个八分音符从缝隙里钻过一列。

**54–55 · 节奏本身开火**：这里贝斯和底鼓退出，打击乐演奏的正是主 riff 的节奏 `x x x . x . . x . x . x . x x x`，于是 **HUD 的字母按 riff 发射**：
- 第 54 小节：名字 **BOMEI 的五个字母**打 riff 的五个重音。
- 第 55 小节：**LV 与 HP 数字**打满整条 riff（**由外向内**，最后 13-14-15 三连 16 分音符）。
- 每个字母：先在原位**颤抖变红** → 从 HUD 里**浮起放大** → **提前一个 16 分音符射出** → **正好在音符上**穿过心刚离开的位置；每一下伴随原版菜单「咔嗒」。被掏空的字位闪红，整排 HUD 随拍泛红（**HP 条始终不动**）。
- 底下是一条稳定的四分音符脉冲：**每拍战斗框四壁向内收一次（150×140 → 68×66）**，暗角 / 去饱和 / 色差 / 上下遮幅逐拍加重；镜头**只做推近**（不左右甩，避免运动模糊），始终让下一个要发射的字母留在画面里。
- 最后一个 16 分音符：镜头扑向红心、画面撕裂发白；**第 56 小节重拍上字母全部归位**。

验收：字母发射序列与 riff 完全一致（列一张表核对 16 分位置）；框收缩每拍一次、共 8 次到 68×66。

## 段 10 · 第 56–63 小节（112.04–128.04 s）· 炮台巨龙 → 竖井 → 第一人称体素

**56–57 · 炮台巨龙**：
- 先是一条蛇：**九个兽颅串在骨头脊椎上**绕场盘旋，每一炮都落在**反拍的和弦重音**上（每拍的「&」）。第 56 小节一次一个兽颅开火。
- 第 57 小节重拍**脊椎炸断**、骨头四散，九个兽颅挣脱成**一圈缓缓旋转的独立炮台**，仍在反拍上两两交叉开火（心站在两条射线的角平分线上）；心在每拍上迈出最小的一步、炮在随后的反拍开火，落点是所有还在扫动的光束最远处。
- 第四拍重军鼓时**炮圈猛地收紧、九个兽颅一起转向**，最后一个反拍同时开火——光束都瞄准中心旁 36 px，形成一个**围住红心的风车**。

**58–59 · 坠落竖井**：
- 第 57 小节最后一个 16 分 Sans 抬手；**第 58 小节重拍手掌压下**：心变蓝（「叮」）、被按到地板上，**地板碎裂、心从破洞里坠下**；战斗框拉伸成**竖井**，速度线由慢到快，巨龙被一起卷到画面外，镜头顺势俯冲、心回到竖井上部。
- 竖井底部的炮台跟着军鼓连射：每一门都从心**所在**车道的下方冒出、锁定、直直向上开火（先每拍一炮，从 58.3 起每个八分音符一炮），心在每一炮前一点横移到相邻车道；第 59 小节第一、三拍直接跨到对面车道。
- **骨头台阶高速向上掠过**（第 58 小节按 riff 重音、第 59 小节每个八分音符一层），每层缺口正好开在心躲到的那条车道；镜头每拍往下踩一步。
- **砸进第一人称**：井底地板从深处升上来的一瞬间，画面直接落进**体素世界**，镜头跟着心加速俯冲、在**第 59 小节第四拍撞地的同一刻穿过心脏**（满屏蓝光），紧接着抬头——半拍之后已经是第一人称，四壁随之升起。

**60–63 · 第一人称体素 3D**（`voxel.js`，远处是公告板 Sans，巨大如审判者）：
- **60**：从重拍起每个八分音符在远处炸起一排**地面骨柱**，朝镜头滚来，下一个八分音符从镜头两侧擦过（镜头**提前侧移**钻进这排的缺口），穿过去后沉入身后。
- **61**：每个八分音符一根骨头沿走廊冲来：**跳过低骨**（低头看它从脚下掠过）、**蹲过高骨**（抬头看它从头顶掠过）、**蓝墙前静止**、**侧移钻过骨栅栏缺口**。
- **62**：**炮台贴脸**（公告板按光束在镜头里的方向转正：朝镜头开火的炮是立着的、下颚朝下）——两门炮从镜头两侧同时开火形成**光之走廊**；正面对视的炮在开火前一个 16 分**侧身躲开**；身后的炮从头顶射过；镜头**急转一圈**时每个 16 分一门炮擦着眼睛开火；**最后一门正对镜头、光炮直接打中心**（白屏 + 红闪 + PlayerDamaged）。
- **63**：被重力甩向墙，**墙里刺出的骨头再次打中心**。两次命中都有红闪和受伤音效；**HP 条从第一次命中起浮现在第一人称画面下方**；KR 规则见 1.5——墙里的骨头几乎把剩下的血全部染紫，紫色数字在之后的旋涡、狂轰、疲惫段一路慢慢往下跳。

验收：巨龙开火全在反拍；竖井每层缺口与心的车道一致；2D→3D 切换无跳帧（同一时刻 2D 心的位置 = 3D 镜头穿过的位置）；`MV.checkPov()` 除 62/63 两次命中外 0 违规。

## 段 11 · 第 64–71 小节（128.04–144.04 s）· 旋涡、榨干他、睡着、推

- **64–65 · 旋涡**（模拟器最终攻击的开头）：每个 16 分音符一门炮穿过中心，心**始终领先旋涡四分之一圈**；单一机位逐渐推近，把竞技场**倾斜成旋转的圆盘**，并被旋涡带着一起转。
- **66–67 · 榨干他**：战斗框碎裂；Sans **每拍挥手、倾尽全力**，左眼燃起一簇**内焰黄、外焰蓝**的火焰（每次出手都更旺）：骨矛钳击、炮台锁定、骨环合拢，心只用**最小、最准的一步**躲开，每一击都正好穿过它刚离开的位置（第 66 小节每八分一步，第 67 小节前半每 16 分一步、每八分一门炮）；随后攻击变慢变少，他开始**出汗**（Sweat1→3），眼中的火苗几次回光后熄灭，最后两门炮**还没开火就垂下、碎掉**。
- **68–69 · 他没力气了**：模拟器最终的重力连甩，**一次比一次慢**（最大下落速度 750 → 480 → 330 → 240 → 90）；左上角浮现「* Sans看起来真的很疲惫了。」（镜头让开文字框，脸始终在画面里）；Sans 流汗、挥手一次比一次慢。第 69 小节他撑着不睡：**眼皮打架（Tired1/Tired2）、慢慢眨一次眼**，扔出最后一下时**闭眼点头打瞌睡**、心落地那一刻**猛地惊醒**，手臂垂下，随即眼睛彻底合上、头慢慢沉下去。
- **70 · 睡着**：呼吸放慢（身体上下起伏变慢）、汗慢慢干掉，「z」一个接一个飘起来。
- **70–71 · 推**：「战斗」按钮够不着——**红心顶着战斗框的墙往按钮推**，先每拍一下、再每八分、最后每 16 分一下；框把 BOMEI / LV 和「战斗」按钮一起罩住，**心踩上「战斗」**。KR 在第 71 小节第三拍扣到 1，随后镜头被拔出第一人称（如尚未拔出）。

验收：重力连甩的最大速度逐次递减可见；入睡的每个表情变化都有时间读到；推框节奏 1/4 → 1/8 → 1/16 加速清楚。
