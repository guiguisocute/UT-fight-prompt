# 第一部分 · 项目说明

## 1.1 一句话

**「他不想打，却必须赢。」** 中立线结界前的国王战。艾斯戈尔**借用**容器里六颗人类灵魂的力量（灵魂始终留在容器里，力量化成一条光带连到三叉戟，**他从不吸收**——吸收是之后小花做的事）。第一次借用的顺序 **黄 → 绿 → 紫 → 蓝 → 橙 → 青**，每一颗带着它主人留下的遗物与一套 2D 机制，背后的长廊变成那个孩子的世界。高潮他七彩全力一击把心打到 1 HP；吃下托丽尔的奶油糖果派，回忆一个家；最后心跃上六个容器，每颗魂把力量借给 Frisk、用自己的方式打他；原作的攻击条回来，最后一击落在音乐的最后一个音上。他跪下、自白、饶恕——一圈白色“友谊颗粒”出现在他周围，黑场（不露小花）。

## 1.2 情绪设计（最重要的导演原则）

> **每一次华丽的攻击背后，都藏着一个他「不忍」的细节；镜头让观众看见红心看不见的东西。**

- **情绪的总开关 = 镜头离他的脸有多近**：0–15 看他像看 Boss（对称、仰拍、目标行与血条——一副面具）→ 16–39 镜头离开他，去看那些容器、从容器里往外看（重量在死去的孩子身上）→ 40–51 镜头失去分寸（旋转、快切：他想在自己撑不住之前把一切结束）→ 52 一切停住 → 53–59 镜头第一次温柔、靠近、温暖（回忆）→ 60–73 一次比一次更靠近他的脸。
- **他是坚毅的战士，脸从不变**：整场战斗都是原作那张战斗面具（低着头、阴影里的眼睛），**不闭眼、不换表情、被打中也不晃、不颤抖**（原作里唯一被打中不会颤抖的怪物）；只在交谈①按原作原话「他的手颤抖了一下」；他的脸只在跪下之后照原作换。
- **他从不直视那颗心**；**他不流泪**。不忍只用别的方式演：不直视、别过头、手。
- **园丁的手**：一双浇花的手握着三叉戟。每次借用灵魂，他松开一只手、摊开爪子伸向那个容器，像捧一朵花那样接住它的光——那是请求，也是道歉；第 60 小节死死握紧；最后松开，三叉戟落地。
- **打击的语法**：打在他身上，**他不动，世界替他动**（见 1.6）。
- 致敬全部 **UT 本地化、不出戏**：不用名牌、横带、汉字警告、BREAK 字等别家界面，全部换成 UT 本来就有的东西（目标行与血条、眼睛闪光帧、红色「!」、「查看」文字、灵魂心）。不用故障、VHS、扫描线、强色散。

- 1920×1080、60 fps；2D 世界 960×540（原作 640×480 布局放在 +160, +30）；精灵原作 2 倍整数缩放、最近邻。约 4 分 10 秒（250 s）。
- 两首音乐（`MV.MUSIC` / `T.tracks`）：

**规则**：
- 中立线，**Frisk LV 1 HP 20**；艾斯戈尔 **HP 3500**（原作），攻击 80 防御 80。

- 原作颜色规则：**橙色只在心移动时穿过，青色（浅蓝）只在心静止时穿过**；绿魂锁住心、给它护盾；紫魂只能沿横线走；蓝魂有重力；黄魂是射击模式。
- 「仁慈」在第三幕被砸碎，**按钮位一直空着、碎片留在原地**，第五幕才飞回重组。

## 1.6 本片专属技术要点

- **结界长廊**（第一幕）：原作结界房间本来就是一根笔直的长方体管道——对录像的嵌套矩形拟合：每一圈地面在消失点下方 0.76 个半宽、顶在上方 6.4 个半宽。体素空间（单位 = 原作屏幕 1 px）：眼睛 (0, −14, 600)，管道从 z = 200 向 −z 延伸（半宽 284、地面 −230），4.2 万单位深，超出 3000 的部分沿视线折进一个 300 长的尖端；墙按画面约 3 px 一格铺体素，每格明暗取自它盖住的那个像素。**透视相机站在管道轴线上、不打光**——看起来就是原作的 2D 画面。光从录像测出来（`tools/make_corridor.py` → `src/corridor.js`）：一道始终朝门里流的波，周期约 6.76 s（墙慢慢变亮约 60% 周期、再较快暗下），越深越晚，门比墙晚约 0.41 周期；相位对齐成**墙在 music1 开始那一刻最白**。
- **多平面伪 3D 布景**（`post2d.js` / `flat.js` / `depth.js`，HD-2D）：四张平面各立在真实深度上被真 3D 相机拍——最远：压扁的走廊（同心矩形）、门里的光、紫光、余烬、远处火星（深 900）；石台、容器、火星与小火苗（深 170）；他、三叉戟、光带、眼睛闪光（深 110）；战斗：框、弹幕、HUD、心（深 0）。每张按距离放大补偿，**相机在“家”时与原作逐像素一致**。相机参数：看的点、zoom、pitch（正 = 低机位仰拍）、yaw、roll、fov（改 fov 不改 zoom = 希区柯克变焦）。俯仰/偏航 ≤ 约 0.5 rad；不做持续的画面旋转。`MV.depthXf` / `MV.toScreen` 把某深度上的点换算到屏幕。每层虚焦用一块固定大小的画布（**不要每帧新建画布**——原工程因此周期性卡到 25–40 ms）。
- **背景：被压扁的结界**——战斗框背后透出门里的光（随整场从冷白走向黎明的金）；长廊的墙压得很暗、光波由 `TL.wave2` 驱动；他的火**不画成一排火舌**，化成从框下黑暗里升起的 2 px 火星与余烬（越往上从黄白褪成橙、暗红，12 fps 闪烁，热的拖尾）、几簇一窜即灭的小火苗、底部一层低低的暖光；`look2.flames` 控制强度（0 熄灭 / 世界在时 0.15 / >1 猛烈）；火星跟着世界的风倒，底鼓一响火光一跳。
- **六个世界**（`worlds.js`，被借用的灵魂改变背景，世界里没有人）：进来时那颗魂的颜色从外往里漫过一圈圈环、世界在环后显出来，他的火星稀下去；出去时火星猛地涌起、一道火线从下往上把它烧掉。半分辨率像素画（每像素 = 世界 2 px）画在最远平面，近处的东西（风滚草、纸页、雪、落叶）在容器层，**永远不进战斗框**。每个世界有自己的时钟（会停）和风。

- **全力一击** `FIN.allOut`（《边狱巴士》语法：定格大姿势 → 一帧切换 → 顿帧 → 释放，镜头骑在戟尖上，七色硬边光带；只有这一击允许超过 2 倍、放大像素）。
- **心的路线**：`B.dodge` 规划器（找最省力的躲法）+ `dance(keys)` 舞步引导（`o.lure` 随时间移动的诱导点，`lureW 1.6`、`startW 0.06`）——**先编心的路线再朝心开火**，否则心几乎不动、没有紧迫感（战斗小节心的位移应在 150–500 px/小节）。冲刺拖 2–3 个渐隐残影；擦弹每次都响（MenuCursor 0.15，音高递增）。
- **火**（`kingfire.js`）：火链网 `B.swing`（**整张网一直倒、不断**，“错开半格”改成整张网往旁边摆半格再摆回来，弯折顺着链流下）、`B.flood` / `B.snake`（「!」火海与单股火链）、火环、火雨、火焰手。
- **体素窗口**（`vox.js` / `vstage.js` / `cage.js`）：浮雕立牌（`MV.kingSnapshot`），进出要么与 2D 构图逐像素一致（`MV.FLAT_CAM`、`TL.cam.flat`），要么是一次有理由的硬切；不叠化；一个窗口 ≤ 4 小节。
- 音效变调 `H.sfx(t, name, vol, {rate})`；眼睛闪光的音高：橙 = EyeFlash ×1.25、青 = ×0.8，底下一层 Drone。

# 第二部分 · 通用框架要求（六个 MV 共用，必须照做）

> 这六部 MV 原本是同一套自研「无状态时间轴 + 像素画布 + WebGL 后期 + 无头浏览器逐帧导出」框架，一部一部迭代出来的。复刻时**先把这套框架搭起来并验证**，再碰任何分镜。

## 2.1 技术栈与目录

- **纯静态网页**：一个 `index.html` 按顺序 `<script src="src/xxx.js">` 加载所有模块；**不用打包器、不用前端框架、运行时零 npm 依赖**。全局命名空间 `window.MV`，每个文件是一个 IIFE，往 `MV` 上挂东西。
- 画布 `<canvas id="mv" width="1920" height="1080">`；**世界坐标 960×540**（原作 640×480 的战斗布局 1:1 居中，左右多出来的地方留给运镜和特效），像素世界按 2 倍放大到 1080p。角色精灵 2 倍像素、心和弹幕 1 倍像素——**和原作一样的混合分辨率**，不要把所有东西统一缩放。
- 2D 用 Canvas2D（`imageSmoothingEnabled = false`，坐标一律 `Math.round`），后期和 3D 用 WebGL（自己写一个 `m3.js` 小矩阵库，不引入 three.js）。
- Node.js（≥18）+ Playwright（Chromium）+ ffmpeg 只用在 `tools/` 的离线脚本里；Python（numpy / scipy / librosa / pillow）只用在分析与素材打包脚本里。

推荐目录（与原工程一致）：

```

src/glyphs.js         中文点阵字形（tools/make_font.py 生成，勿手改）

src/engine.js         Track / Steps / TL 事件仓库 / 冲击 / 粒子
```

## 2.2 核心原则：一切都是时间 t 的纯函数

- 任何一帧都必须能**单独**渲染出来：实时播放、拖动进度条、逐帧导出、倒带（VHS 回放）、慢动作，全部走同一套代码。
- **禁止** `Math.random()`、禁止跨帧累积状态（“上一帧的位置 + 速度”）。随机一律用基于哈希 / 种子的确定性函数：`U.hash(x)`、`U.hash2(x,y)`、`U.noise(x)`、`U.rng(seed)`（mulberry 类）。
- 物理（重力心、蓝心砸墙、风推心）要么写成解析式，要么**预先离线模拟后烘焙成采样**（`Track.bake(t0, dt, {x:[...], y:[...]})`），播放时只插值。
- 引擎 API（建议照抄这套语义）：
  - `new MV.Track(init)`：多通道关键帧轨道。`.to(t0, t1, vals, ease)`、`.set(t, vals)`、`.hop(t0, t1, vals, h)`（抛物线跳）、`.bake(...)`、`.at(t)` 返回该时刻全部通道值。段与段从“上一段到达的值”混到目标值。
  - `new MV.Steps(v)`：分段常量（姿态、模式、开关），`.set(t, v)`、`.at(t)`、`.since(t)`（当前值已持续多久）。
  - `TL.add({t0, t1, z, draw(ctx, emi, t, S), hit?(t, x, y)})`：一个“活在 [t0,t1) 的可绘制事件”。按 z 排序绘制。`TL.active(t)` 用二分找出当前活着的事件。会伤人的弹幕必须实现 `hit(t, x, y)`（该时刻点 (x,y) 是否在弹幕里），页面暴露 `MV.checkHits(t0, t1)` 给 check.cjs 用。
  - `TL.impact(t, {amp, dx, dy, zoom, rot, inv, bw, flash, ca, dur})`：冲击——震屏（方向踢 + 随机抖）、推镜、旋转、反相帧、黑白帧、闪白、色差，全部随时间指数衰减，由 `TL.fxAt(t)` 汇总。
  - `TL.glitch(t0, t1, amt)`、`TL.shock(t, {...})`（屏幕冲击波）、`TL.burst(t0, {...})`（解析式粒子爆发，无模拟状态）、`TL.ring(...)`（像素圆环）。
  - 时间重映射：`TL.remap(t0, t1, f)`（画面显示 f(t) 而不是 t，用于 VHS 倒带）、`TL.hitStop(t, hold, catchUp)`（顿帧后用 Hermite 曲线追回音乐，无跳变）、`TL.slowmo(t, W, a)`（先慢后快、首尾速率为 1 的慢动作）。**音乐永远不停，只有画面时间被重映射**。
  - 音效表：`TL.sfx.push({t, name, vol, rate, end, fade})`，播放器用 WebAudio 提前 0.25 s 排程，导出时由 render.cjs 混进音轨——两边读同一张表。
- 每个 `draw(ctx, emi, t)` 都拿到两张画布：`ctx` 是颜色层，`emi` 是**自发光层**（辉光的来源）。会发光的东西（光炮、魔法、眼睛、火）要同时往 `emi` 画。

## 2.3 音乐网格（卡点的唯一依据）

- `tools/analyze_music.py`（librosa）分析音乐，写出 `src/analysis.js`：`window.MV_ANALYSIS = { bpm, offset(第 0 小节第 0 拍的秒数), sixteenth, barLength, duration, bars, slots:{kick, snare, tone, full}(每个 16 分音符格子的实测起音强度 0–1), env:{rms,...}(包络), envFps, sections:[{bar0, bar1, name}] }`。
- 先用 `beat_track` 粗估 BPM，再**用 16 个相位逐一和主节奏型做相关**挑出真正的第一拍；检查全曲是否恒速（游戏原曲通常是恒速的，同人混音/未完成版要分段核对）。
- `util.js` 里提供 `T.at(bar, beat=0, s16=0)`（小节/拍/16 分 → 视频秒，允许小数、溢出、负数）、`T.slot(t)`、`T.barOf(t)`、`T.acc(slot, band)`、`T.env(t, band)`、`T.pulse(t, period)`、`T.accPulse(t, band)`、`T.section(t)`。
- **所有事件都写成 `T.at(...)`**，不允许出现手写的“37.42 秒”。
- 卡点约定：弹幕在音符**上**到达最长 / 命中；炮在拍上开火；心的闪避在**前一个八分音符**完成；镜头硬切落在重拍；震动强度、粒子数量可以读该 16 分格的实测强度 `T.acc`。
- 冷开场、多首曲子拼接时，`T.pre` / `T.off` 等偏移写在 util.js 一处，`MV.MUSIC = [{src, t0, dur, off}]` 列出每个音频文件在视频时间轴上的起点（`src` 是相对 `index.html` 的路径，本仓库里是 `asset/music/…`）；播放器和导出都读它。

## 2.4 素材管线

- `tools/import_assets.py`：把 `asset/` 里的精灵表切片（按 spriters-resource 表格的格子或手工坐标）、透明化、去背景，原作音效 wav/ogg 用 ffmpeg 转 mp3，统统打成 `src/assets.js`：`window.MV_ASSETS = { img:{name: dataURI}, sfx:{name: dataURI}, meta:{锚点/帧表} }`。**这样双击 index.html（file://）也能跑，没有 CORS 问题。**
- 战斗 UI（心、四个按钮、HP/KR、攻击靶、斩击、对话气泡、字体、菜单音效）统一用 `asset/ui-kit-c2-sans-fight/`（原作素材，带锚点 meta.json）。
- 中文：`tools/make_font.py` 扫描 `src/*.js` 里用到的所有非 ASCII 字符，用 16 px 宋体（`C:/Windows/Fonts/simsun.ttc`，或 GNU Unifont）渲染成 1-bit 点阵，写进 `src/glyphs.js`；画面上所有中文都是点阵字，和原作中文版的观感一致。英文/数字用原作位图字体。
- 角色动作：优先用原作精灵帧；需要原作没有的动作时，**把精灵切成部件做骨骼 rig**（关节点手工标定，或在录像里逐帧拟合），而不是重画一个风格不同的角色。
- 生成文件（analysis.js / assets.js / glyphs.js）**永远不手改**，改脚本重新生成。

## 2.5 渲染层次与后期（post.js）

- 每帧：`scene.render(t)` → 求值所有 Track / Steps → 在离屏的**世界画布**（960×540 + 四周留边，供运镜不露边）上画背景 → 弹幕 → 角色 → 战斗框/HUD；同时画**发光层**；再画不受相机影响的**屏幕层**（字幕、遮幅、读档界面等）。
- `post.js`（WebGL）：把世界画布当作 3D 空间中的一张平面，用**真的 3D 透视相机**去拍（pitch / yaw / roll / dolly / 平移），远处可有一层视差虚空网格；然后依次叠加：双层辉光（emi 层）、径向色差、黑白反相冲击帧、黑白阈值帧、故障切片 / RGB 撕裂、甩镜运动模糊、VHS（倒带时）、点阵网格 / 扫描线、暗角、胶片颗粒。
- 镜头语言要“现代”但画面要“原作”：**像素永远是方的、不糊**（后期在 1080p 上做，世界层最近邻放大）。

## 2.6 播放器（main.js / index.html）

- 空格 / Z / 回车：播放暂停；← →：±2 s（按住 Shift：±1 小节）；D：调试信息（`t / 小节 / 拍 / 16 分 / 段落名`）；H：干净画面（隐藏 UI，截图用）；点击底部进度条跳转。
- URL 参数：`?t=64`（从 64 秒开始）、`?lat=0.03`（音画延迟校准）、`?lab=<name>`（样片）、`?render=1&w=1920&h=1080`（导出模式：只暴露 `MV.exportFrame(t)` 和 `MV.ready`）、`?clean`。
- 音乐用 `<audio>` 元素按 `MV.MUSIC` 的偏移播放并以它为时钟；音效用 WebAudio 解码后按 `TL.sfx` 排程。第一次按播放要等音效全部解码完再开始。

## 2.7 工具（tools/）

> 本项目的 `tools/` 已经附上原工程的全部脚本（路径改成了本仓库布局），**先读 `tools/README.md`**。下表是通用的那几样；各项目专属的检查工具（例如 mft 的 `beatcheck.cjs`、mtt-neo 的 `cutaudit.cjs` / `camcheck.cjs`）也在里面。可以直接用，也可以照着重写，但页面要先提供它们用到的接口（`MV.ready`、`MV.exportFrame`、`MV.checkHits` 等）。

| 脚本 | 作用 |
| --- | --- |
| `serve.cjs` | 无缓存静态服务器（预览 `http://localhost:4173`） |
| `pw.cjs` | 解析 Playwright；页面一律用 `file:///…/index.html?…` 打开并加 `--allow-file-access-from-files`；`--gpu` 时 `--use-angle=d3d11 --ignore-gpu-blocklist --enable-gpu-rasterization`，否则 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` |
| `frames.cjs <outDir> <t...> [--gpu --w --h --lab]` | 渲染指定时刻的静帧（**最常用的检查手段**） |
| `render.cjs [--t0 --t1 --fps=60 --w --h --workers --gpu --vcodec=h264_nvenc --frames=dir --out]` | 多个无头 Chromium 并行调用 `MV.exportFrame(t)` 拿 JPEG → 管道喂给 ffmpeg；同时把 `MV.MUSIC` 的各段音乐按偏移解码（`-af aresample=resampler=soxr`）+ `TL.sfx` 全部音效混成 48 kHz WAV，带 5 ms 前视峰值限制器（只压冲出去的瞬态），AAC 320k，`-movflags +faststart` |
| `check.cjs [bar0 bar1]` | 以 240 Hz 采样整段：白色弹幕/光束**从不碰到心**（剧本写明的命中除外）、蓝色弹幕只在心静止时穿过、弹幕密度/节奏统计；有问题就打印小节·16 分位置 |
| `sheet.py` / `contact_sheet.py` | 把一串静帧拼成联系表（contact sheet），一眼看完一段 |
| `analyze_music.py` / `explore_*.py` / `plot_music.py` | 音乐分析与可视化（频段能量、节奏型相关、自相似矩阵分段） |
| `import_assets.py` / `slice_sheet.py` / `make_font.py` | 素材打包、精灵表切片、点阵字 |
| `eval.cjs` | 在页面里执行一段 JS 打印结果（查某时刻某轨道的值） |

导出规格：**1920×1080、60 fps、H.264（NVENC：`-preset p5 -rc vbr -cq 19 -b:v 0`；或 libx264 `-crf 20 -tune animation`）、yuv420p、AAC 320k**。不加 `--gpu` 用 SwiftShader 也能跑，只是很慢。

# 第三部分 · 工作方式（最重要：逐步推进，切勿一次成片）

> ⚠️ **再说一遍：不要试图一次性写完整部 MV 再导出看效果。** 原作每一部都是几十轮“做一小段 → 出静帧 → 出小样 → 对照原作和剧本挑毛病 → 改”迭代出来的。一次成片的结果一定是：节奏全错位、弹幕穿心、镜头乱跳、角色走样，而且错误叠在一起无从下手。

## 3.1 必须遵守的推进节奏

1. **阶段 0 · 读与看（不写代码）**
   - 把本 PROMPT 从头读到尾，列出 `asset/` 里每个文件是什么、会用在哪一段。
   - 用 ffmpeg 从 `asset/record/` 的原作录像里抽帧（例如每 0.5 s 一张，再拼联系表），对照本文的分镜逐段看懂原作的 UI 位置、弹幕形态、角色动作、文字内容。把观察写进 `work/notes.md`。
   - 输出：素材清单 + 你理解的分段表（小节范围 → 内容），**先给用户确认**。
2. **阶段 1 · 框架骨架**
   - 搭 `index.html` / util / engine / main / scene / post / serve / frames / render / check。
   - 跑音乐分析，**验证网格**：做一个“节拍器样片”（每拍闪一次、每小节第一拍大闪、屏幕角落显示小节号），导出 20–30 秒带声音的小样，**亲自核对**画面闪光和听到的鼓点是否对齐（误差 < 1 帧）。网格不对，后面全部白做。
   - 输出：节拍器小样 + `analysis.js` 的关键数字（BPM、offset、总小节数、段落表）。
3. **阶段 2 · 素材入库**
   - 切精灵、打包 assets.js、生成字形；做一张“素材总览”静帧（所有精灵、所有动画帧、所有字体一字排开），检查透明边、锚点、尺寸是否正确。
   - 搭原作战斗场景的**静态还原**：一帧和原作录像截图并排对比，UI 像素位置对上为止。
4. **阶段 3 · 逐段编舞（核心循环，每次只做 2–8 小节）**
   - 写这一段的 `tl_xxx.js`。
   - `frames.cjs` 渲染这一段的关键时刻静帧（每个重拍、每个命中、每次镜头切换前后各一张），拼成联系表自己先看。
   - `check.cjs <bar0> <bar1>` 跑碰撞与密度检查，必须 0 违规。
   - `render.cjs --t0 --t1` 导出**这一段 + 前后各 1 小节**的带声小样，完整看一遍、听一遍：卡点是否在音符上、镜头是否有莫名的跳变、文字是否读得完。
   - 把小样和联系表交给用户确认，**得到确认再做下一段**。
   - 每段做完 `git commit`，提交说明写“小节范围 + 做了什么”。
5. **阶段 4 · 段与段的衔接**：每做完相邻两段，专门检查交界处前后 2 小节（镜头连续性、状态是否突变、HP / UI 状态是否一致）。
6. **阶段 5 · 全片**：所有段都单独通过后，才导出整片；整片再从头看一遍，列问题单逐条回到阶段 3 修。
